# Неубиваемый стек

> Мы рассмотрели простейшую структуру данных - стек (буфер LIFO) и его реализацию в Си с точки зрения объектно-ориентированного программирования. Для этого мы применили логическую группировку данных (структуру, struct) и семейство функций (методов), связанных с ней. Типичными методами являются инициализация (конструкция, Stack_ctor), деинициализация (деструкция, или очистка, Stack_dtor), тихая верификация (Stack_OK) и отладочный дамп (Stack_dump). Первые две последних функции поддерживаются С++ как конструкторы и деструкторы; для последних двух нет явно поддерживаемых эквивалентов, но без них легко допустить ошибку даже в простой структуре данных и очень тяжело ее поймать. Также рассмотрели стратегии двойной проверки для динамической верификации объектов стека.

# Формализация задачи

Требуется реализовать стек: простейшую структуру данных, поддерживающую операции добавления элемента в конец и удаления элемента с конца. Структура должна быть защищенной от различного рода ошибок и вмешательств: никакие действия, которые пользователь может сделать со стеком, не должны приводить к падению программы, а информация об ошибке должна быть доставлена любой ценой.

# Архитектура структуры данных

Структура данных поддерживает элементы любого фиксированного размера. По умолчанию - int. В структуре доступны поля size и capacity, позволяющие узнать количество элементов в стеке (`size`), а также количество элементов, под которые выделена память (`capability`). Выполнен инвариант `capability >= size`.

```c
typedef int stack_el_t;

typedef struct {
    stack_el_t* data;
    size_t size;
    size_t capacity;
    // unsigned long long _data_hash
    // unsigned long long _struct_hash
} stack_t;
```

`data` - указатель на динамическую память, в котором лежат сами хранимые элементы стека. В отладочной версии (флаг компиляции `-DDEBUG`) данные, располагающиеся по указателю `data`, защищены с помощью стековых канареек и располагаются в следующем формате:

| Размер, байт |      4    |     8     |  n * st_elem_size  |      8     | 
| ------------ | --------- | --------- | ------------------ | ---------- |
| Поле         | Signature | Canary 1  |        Data        |  Canary 2  |

В релизной версии защита стека канарейками отключена:

| Размер, байт |     4     |  n * st_elem_size  |
| ------------ | --------- | ------------------ |
| Поле         | Signature |        Data        |

Сигнатура стека (`Signature`) позволяет определить, лежит ли в памяти именно стек. Канарейки позволяют отлавливать ошибки класса выходов за границу массива

Кроме прочего, в отладочном режиме стек защищён хешированием: во время работы со стеком поддерживаются поля хешей, которые защищают структуру от локальных случайных (или специальных) непредусмотренных изменений.

## Методы

Все доступные пользователю структуры данных функции находятся в заголовочном файле `mystack.h`. Сигнетуры функций следующие:

### StackCtor

Конструктор стека. Инициализирует структуру данных.

```c
stack_err_t StackCtor (stack_t* st_ptr, size_t capacity);
```

Параметры:

* `stack_t* st_ptr` - указатель на будущий стек. Должен указывать на память, размер которой не меньше размера структуры `stack_t`, всё предыдущее содержимое по указателю при инициализации будет перезаписано;

* `size_t capability` - вместимость стека, то есть количество элементов, под которое требуется выделить память. При необходимости количество памяти будет увеличено.

Возвращамое значение:

* `stack_err_t` - тип возможных ошибок при инициализации. См. пункт обработка ошибок

Пример использования:

```c
stack_t st = {};

StackCtor (&st);

// Стек сконструирован. Теперь с ним можно работать
```

### StackPush

Добавляет элемент на вершину стека.

```c
stack_err_t StackPush (stack_t* st_ptr, stack_el_t elem);
```

Параметры:

* `stack_t* st_ptr` - указатель на стек. Должен указывать на полноценную инициализированную `stack_t`, перед выполнением операции будет проверен на наличие ошибок в памяти;

* `stack_el_t elem` - элемент, который будет добавлен на вершину стека.

Возвращамое значение:

* `stack_err_t` - тип возможных ошибок при выполнении операции. См. пункт обработка ошибок

Пример использования:

```c
// Предполагается сконструированный стек (здесь назван st), см. пример к StackCtor

// Положим число 52 в стек
stack_err_t res = StackPush (&st, 52);
if (res != STCK_OK) {
    // Обработка возможных ошибок
    // ... 
}
```

### StackPop

Удаляет элемент с вершины стека и записывает его по предоставленному указателю.

```c
stack_err_t StackPop (stack_el_t* dst_elem, stack_t* st_ptr);
```

Параметры:

* `stack_el_t dst_elem` - указатель на элемент, который будет снят с вершины стека. Должен указывать на память, размер которой не меньше `stack_el_t`;

* `stack_t* st_ptr` - указатель на стек. Должен указывать на полноценную инициализированную `stack_t`, перед выполнением операции будет проверен на наличие ошибок в памяти.

Возвращамое значение:

* `stack_err_t` - тип возможных ошибок при выполнении операции. См. пункт обработка ошибок

Пример использования:

```c
// Предполагается сконструированный стек (здесь назван st), см. пример к StackCtor

// ...

// Предположим, ранее мы положили число 67 на стек
stack_err_t res = StackPush (&st, 67);

// ...

stack_el_t x = 0;
res = StackPop (&x, &st);
if (res != STCK_OK) {
    // Обработка возможных ошибок
    // ... 
}

printf ("%d", x);
// 67
```

### StackDtor

Деструктор стека. В целях безопасности заполняет память, в которой лежал стек, случайными значениями и освобождаёт её.

```c
stack_err_t StackDtor (stack_t* st_ptr);
```
Параметры: 

* `stack_t* st_ptr` - указатель на стек. Должен указывать на полноценную инициализированную `stack_t`, перед выполнением операции будет проверен на наличие ошибок в памяти.

Возвращамое значение:

* `stack_err_t` - тип возможных ошибок при выполнении операции. См. пункт обработка ошибок

Пример использования:

```c
// Предполагается сконструированный стек (здесь назван st), см. пример к StackCtor

// ...

// Какая-то работа со стеком

// ...

stack_err_t res = StackDtor (&st);
if (res != STCK_OK) {
    // Обработка возможных ошибок
    // ... 
}
```

### GetErrorString

Позволяет получить строковое толкование полученной ошибки. Во избежание утечек памяти требуется освободить память по возвращенному указателю.

```c
const char* GetErrorString (stack_err_t errcode);
```
Параметры: 

* `stack_err_t errcode` - полученный код ошибки

Возвращаемое значение:

* `const char*` - строковое значение полученных ошибок (возможно, не одной). Если ошибок будет несколько, ошибки будут выведены через `|`.

Пример использования:

```c
// Где-то получили stack_err_t res; res != STCK_OK
if (res != STCK_OK) {
    const char* errstring = GetErrorString (res);
    printf ("Error: %s", errstring);
    free (errstring);

    // Error: <ERRCODE> <--- Here will be real errcode(s)
}
```

## Типы

Во избежание ошибок, для работы со стеком используются исключительно именованные типы структуры данных.

### stack_t

Позволяет работать с самой структурой данных.

```c
typedef int stack_el_t;

typedef struct {
    stack_el_t* data;
    size_t size;
    size_t capacity;
    // unsigned long long _data_hash
    // unsigned long long _struct_hash
} stack_t;
```

### stack_el_t

Тип элемента стека. Может быть изменён до компиляции

```c
typedef int stack_el_t;
```

### stack_err_t

Тип возможных возвращаемых ошибок. Для работы с ним см. раздел обработки ошибок

```c
typedef uint32_t stack_err_t;
```

# Обработка ошибок

Документированный тип `stack_err_t` - тип, требуемый для обработки ошибок. Является 32-битным типом данных, на один тип ошибки выделяется один бит. Для того, чтобы узнать, произошла ли та или иная ошибка, требуется провести операцию побитовой конъюнкции:

```c
if (res & STCK_<errcode>) {
    // Ошибка произошла
}
```

С помощью функции `GetErrorString` можно получить строковое значение ошибки. Список ошибок приложен далее:

## Errcodes

| Код ошибки                        | Режим          | Толкование                                                                                                                              |
| --------------------------------- | -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `STCK_OK`                         | Любой          | Ошибок не произошло. Всё хорошо                                                                                                         |
| `STCK_UNACCESSIBLE`               | Любой          | Переданный в работу указатель не является доступной памятью (возможно, 0)                                                               |
| `STCK_DATA_UNACCESSIBLE`          | Любой          | Указатель, по которому лежат данные (`stack_t.data`) в переданной в работу структуре данных не является доступной памятью (возможно, 0) |
| `STCK_INVALID_SIGNATURE`          | Любой          | Указатель, по которому лежат данные (`stack_t.data`) в переданной в работу структуре данных не является валидными данными стека         |
| `STCK_WRONG_CAPACITY`             | Любой          | В переданной в работу структуре данных значение вместимости стека повреждено                                                            |
| `STCK_WRONG_SIZE`                 | Любой          | В переданной в работу структуре данных значение количества элементов повреждено                                                         |
| `STCK_SIZE_GREATER_THAN_CAPACITY` | Любой          | В переданной в работу структуре данных значения количества элементов превышает вместимость                                              |
| `STCK_EMPTY`                      | Любой          | Попытка снять элемент с вершины пустого стека                                                                                           |
| `STCK_WRONG_FIRST_CANARY`         | Только отладка | Повреждена левая стековая канарейка                                                                                                     |
| `STCK_WRONG_SECOND_CANARY`        | Только отладка | Повреждена правая стековая канарейка                                                                                                    |
| `STCK_WRONG_DATA_HASH`            | Только отладка | Неверный хеш данных стека                                                                                                               |
| `STCK_WRONG_STRUCT_HASH`          | Только отладка | Неверный хеш самой структуры стека                                                                                                      |

# Полный пример использования

```c

// Выделяем необходимую память на стеке. Память желательно инициализировать
stack_t st = {};

// Вызываем конструктор для начала работы со структурой данных
stack_err_t res = StackCtor (&st);
if (res != STCK_OK) {
    // ...
}

// Доавление элементов на стек и удаление их оттуда
res = StackPush (&st, 67);
if (res != STCK_OK) {
    // ...
}

stack_el_t x = 0;
res = StackPop (&x, &st);
if (res != STCK_OK) {
    // ...
}

// Пример обоработки ошибок: удаление из пустого стека

res = StackPop (&x, &st);
if (res != STCK_OK) {
    const char* errstring = GetErrorString (res);
    printf ("Error: %s", errstring);
    free (errstring);

    // Error: STCK_EMPTY
}

printf ("%d", x);
// 67

// Освобождаем память
StackDtor (&st);
```
